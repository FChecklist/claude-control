## Real root cause of the "blocked" -> "failed" outcome
The task's real, in-scope deliverable (an external-repo GitHub PR audit
comment) left **zero commits in this task's own repo** (`claude-control`,
`files_modified: []`). When the worker finished, its supervisor tried to
resolve/create a PR for the task's own branch
(`worker/task-20260813-131102-real-tier-1-independent-audit-of-veridia`)
and correctly failed (`gh pr create` -- no commits between master and that
branch) and correctly refused to fall back to an unrelated PR, per
`task.yaml`'s own final note. It set `status=blocked` and stopped -- no
live process after `13:26:52`.

`reconcile_stale_running_workers.py`'s STEP 3 then swept this row (its job:
confirm real systemd state for running/dispatched rows and write back a
real terminal status), saw `ActiveState=inactive` + `task.yaml
status=blocked` + no commit evidence, and -- correctly, per its own
conservative rule ("no real unmerged commit evidence accepted") -- wrote
`status=failed` rather than guessing a completion.

That conservative default is defensible as a *generic* rule (never assume
success without evidence), but it is a **category mismatch** for this
specific task, the same shape already identified twice in this repo's own
history (`UMR-20260813-085615-c1dc` -> `completed`,
`UMR-20260813-100854-e8a1` -> `completed_unmerged`): a task whose real,
correct scope is external-repo audit/merge produces no same-repo commit,
so branch/commit-shaped evidence checks find nothing, even though a real,
independently-verifiable deliverable exists elsewhere (here: the live
`AUDIT:PASS` comment on PR #292, plus real confirmation that PR #292's own
commit `ff328e7` is a genuine, existing, not-yet-merged commit -- the
`completed_unmerged` evidence shape exactly). This occurrence differs from
both prior ones only in that the correct real outcome was "no merge, and
correctly so" rather than "merge succeeded" (`c1dc`) or "merge still
pending" (`e8a1`) -- but the evidence category is the same as `e8a1`: a
real, existing, not-yet-merged commit.
