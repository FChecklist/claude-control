## Real root cause
The `killed` label was a **false negative** caused by a cross-repo blind
spot in `reconcile_owner_dispatch_status.py`'s PR lookup: it calls
`gh pr list --repo FChecklist/{repo}` using the `repo` value stored on the
umr_tasks row / task.yaml (`claude-control`), and never checks any other
repo. This task's real, correct engineering decision -- put the fix where
the changed files actually live (`veridian-scripts`), not in the task's
nominally "owning" repo (`claude-control`) -- put its PR outside that
lookup's blind spot. With `pr_match = None` and systemd `inactive`, the
reconciler's `not pr_match and real_active in (...)` branch fired and wrote
`killed`, even though a real, merged, Tier-1-audited, live-deployed PR
existed the whole time.

This is not a hypothetical: this exact reconciler is now live on a
~10-minute cron (`status-remediation-tick.py`), so any future task that
correctly opens its PR in a different repo than its own `task.yaml repo:`
field will be misclassified the same way. Recorded here as a known,
real, currently-unfixed gap for a future task -- not fixed in this RCA,
since fixing it is new scope beyond "determine the real root cause and
record the real terminal outcome for this one row," and the reconciler's
own docstring explicitly favors fail-open/`NEEDS_AI_JUDGMENT` over
guessing; a repo-lookup fix needs its own dedicated verification.
