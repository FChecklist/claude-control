fix(resource_governor): Stage 6 must ignore a parenthetical PR citation in this task's own title (UMR-20260814-060148)

Follow-up to UMR-20260814-015201/PR #345 (the merged over-broad
duplicate-guard fix). #345's hint_repo-scoping closes the specific reported
incident (cross-repo collision) but leaves a narrower same-repo gap open: a
task whose own title cites a PR number only as a parenthetical aside (e.g.
"...(incl PR 322)...") rather than claiming it as its own target can still
false-positive-block when that number happens to belong to a real PR in the
SAME repo as hint_repo, with no _DISCLOSURE_CITATION_RE disclaimer language
on the candidate side.

New helper _title_pr_reference_is_citation_only(text, pr_num): the
mirror-image check to the existing _DISCLOSURE_CITATION_RE (which inspects
the CANDIDATE PR's title) -- this one inspects THIS task's OWN title,
excluding a bare "PR NNN" reference from Stage 6 matching when it falls
strictly inside a parenthetical span.

Salvaged as the one piece of real unique value found in superseded
veridian-scripts PR #342 before closing it as redundant with #345 -- see
task-20260814-060148's progress doc for the diff that established this was
not already covered by #345, and that everything else in PR #342 (the Stage
6 cross-repo scoping, the reuse_verdict_engine task_kind scoping, and 6 of
PR #342's 8 new tests) was functionally identical to what #345 already
shipped.
