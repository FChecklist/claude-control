## Root cause of the mislabel: a category-mismatch bug in `reconcile_stale_running_workers.py`
`decide_and_apply()`'s `_completion_candidates()` (STEP 3) only gathers
evidence from three sources, none of which can ever see this task's real
deliverable:

1. `task.yaml`'s own `completion_evidence.commit_sha`/`.file_path` (never
   set here -- this task's flow ends at `blocked`, not a structured
   completion write).
2. `git ls-remote` the task's own `branch` in its own `repo`
   (`claude-control`) -- zero commits, so no real tip to offer (and would
   likely also fail `_task_ever_had_real_edits()`).
3. The last checkpoint's `recent_commits[0]` -- the *ambient* repo HEAD at
   checkpoint time, not this task's own deliverable.

None of these three inspect `outputs_json.repo` (`veridian-scripts`, set
at dispatch time from the SPEC's own `outputs_json.repo` field) or the
task's own `completed_steps` text citing **PR #300** in a different repo.
So the sweep never even looked in the one place the real evidence lives,
concluded "no real unmerged commit evidence accepted", and wrote
`status=failed`.

This is the **same category-mismatch shape** already independently
diagnosed for `reconcile_owner_dispatch_status.py`'s `classify_row()` in
`RCA_20260813_UMR-20260813-085615-c1dc.md` (c1dc) and referenced there
against `UMR-20260813-100854-e8a1` (e8a1): a task whose real, correct
scope is external-repo action produces zero commits in its own dispatch
repo, the supervisor correctly refuses to fabricate a same-repo PR, and a
downstream automated status-correction mechanism then misreads that as
"no deliverable" because its evidence search never looks outside the
dispatch repo. c1dc and e8a1 hit `classify_row()`; this row hit the
independent, structurally similar `_completion_candidates()` in the
sibling reconciler script -- same underlying gap, different code path.

The correct terminal status per this system's own established convention
(see e8a1: real PR still unmerged at RCA time -> `completed_unmerged`) is
`completed_unmerged`, not `failed`: real work happened, a real artifact
(PR #300, real commit, confirmed NOT yet an ancestor of `origin/main` via
`git merge-base --is-ancestor` exit 1) exists and is awaiting Tier-1 audit
-- exactly what `completed_unmerged` is for.
