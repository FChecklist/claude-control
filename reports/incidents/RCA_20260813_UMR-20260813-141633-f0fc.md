## Root cause: a hardcoded `origin/main` in the real completed-status gate
`superboss-register.py::_is_umr_terminal_commit_ancestor_of_main()` (the
one function `mark-umr-terminal --status completed` trusts to decide
whether a commit is really merged) hardcoded the literal ref
`origin/main` for both its `git fetch` and `git merge-base
--is-ancestor` calls:

```python
runner(["git", "fetch", "origin", "main"], cwd=repo_root)
...
result = runner(["git", "merge-base", "--is-ancestor", sha, "origin/main"], cwd=repo_root)
```

`claude-control`'s real default branch is **`master`**, not `main`
(confirmed live: `git remote show origin` -> `HEAD branch: master`; there
is no `main` ref in this repo at all). So for every UMR whose
`--repo claude-control` and whose commit is genuinely merged,
`git fetch origin main` fails (no such ref) and `git merge-base
--is-ancestor <sha> origin/main` fails with "unknown revision" --
`_is_umr_terminal_commit_ancestor_of_main()` fails closed (by design, for
safety) and returns `False`, so the gate concludes "not (yet) an
ancestor" and downgrades a real `completed` claim to
`completed_unmerged` (or refuses `--status completed` outright when
called directly). This is a **systemic** bug, not specific to this one
UMR: it silently misclassifies *every* genuinely-merged commit in any repo
registered in `DEFAULT_OCID_RESOLVER_REPO_LOCAL_PATHS` whose default
branch isn't literally named `main` -- currently just `claude-control`,
but the bug would recur for any future repo in the same situation.

`veridian-scripts` itself (the repo `superboss-register.py` lives in)
happens to use `main` as its real default branch (confirmed via `gh repo
view`), which is exactly why this bug was never caught by the existing
test suite: `tests/test_mark_umr_terminal_structured_evidence.py`'s one
real-git-repo test (`test_cli_refuses_completed_for_real_unmerged_commit_against_real_git_repo`)
builds its fixture repo with `git init -b main`, so it could never exercise
the `origin/main`-hardcoded path against a non-`main` default branch.

## Fix shipped
`_is_umr_terminal_commit_ancestor_of_main()` now resolves the repo's real
default branch via `git symbolic-ref refs/remotes/origin/HEAD` (the same
real signal `_git_default_branch()` elsewhere in this same file already
uses for worktree/PR creation) before fetching/comparing, falling back to
`main` only if that lookup itself fails:

```python
default_branch = "main"
try:
    head_ref = runner(["git", "symbolic-ref", "refs/remotes/origin/HEAD"], cwd=repo_root)
    if head_ref.returncode == 0 and head_ref.stdout.strip():
        default_branch = head_ref.stdout.strip().rsplit("/", 1)[-1]
except Exception:
    pass
...
result = runner(["git", "merge-base", "--is-ancestor", sha, f"origin/{default_branch}"], cwd=repo_root)
```

Applied in two places, both real:
1. **Live hotfix**, directly on the deployed
   `/opt/veridian/scripts/superboss-register.py` -- so `mark-umr-terminal`
   is correct on this box immediately, matching this same repo's own
   established precedent of live-patching a confirmed real bug in a
   deployed script (see `RCA_20260813_UMR-20260813-120128-4223.md`'s
   "fix genuinely LIVE on this box: `dispatch-tick.py`").
2. **Real PR against the source repo**:
   [`veridian-scripts#310`](https://github.com/FChecklist/veridian-scripts/pull/310)
   (branch `fix/umr-terminal-ancestor-check-non-main-default-branch`,
   commit `089e589`), so the fix survives the next `deploy-live-scripts.sh`
   cycle instead of being silently overwritten.

Added a real regression test,
`test_cli_accepts_completed_for_real_merged_commit_on_non_main_default_branch`:
builds a real local git repo with `master` as its default branch, real
`origin` remote with `HEAD` pointed at `master`, a real feature commit
later really merged. Manually confirmed this test **fails against the
pre-fix code** (`assert 1 == 0`, refused with "NOT (yet) a real ancestor
of origin/main") and **passes against the fix**. Full existing suite
(`tests/test_mark_umr_terminal_structured_evidence.py`, 17 tests) and a
broader `-k "ancestor or umr_terminal or mark_umr"` sweep (26 tests)
both pass clean.
